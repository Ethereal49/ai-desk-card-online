# Open-Source Readiness Technical Design

## Design Summary

The repository remains a static e-ink dashboard. This task adds a public
project entry point, executable contributor/governance paths, deterministic
continuous integration, and generic deployment examples around the existing
architecture. It does not introduce a package runtime, backend, framework, or
new live-data behavior.

The work stays in one Trellis task because the documentation, configuration
contract, CI, screenshot, GitHub metadata, and branch cleanup all depend on one
coherent branch snapshot. Splitting them would create ordering dependencies and
duplicate integration gates rather than independently shippable children.

## Repository Surface

### New Public Files

- `README.md`: newcomer-facing product entry point and quick start.
- `LICENSE`: exact MIT license text with the approved copyright holder.
- `CONTRIBUTING.md`: repository workflow, scope boundaries, deterministic
  checks, screenshot expectations, and privacy rules.
- `SECURITY.md`: supported-version statement and private-reporting procedure.
- `CODE_OF_CONDUCT.md`: Contributor Covenant 2.1 with executable enforcement
  contacts. Public, non-sensitive concerns may use a normal issue; confidential
  conduct reports use GitHub private vulnerability reporting with a
  `[Code of Conduct]` title prefix.
- `.github/ISSUE_TEMPLATE/bug_report.yml` and
  `.github/ISSUE_TEMPLATE/feature_request.yml`: structured issue forms.
- `.github/ISSUE_TEMPLATE/config.yml`: enables blank issues for questions that
  do not fit a form while pointing security reports to `SECURITY.md`.
- `.github/pull_request_template.md`: plan, privacy, test, and e-ink review
  checklist.
- `.github/workflows/ci.yml`: deterministic, read-only validation.
- `docs/assets/dashboard-preview.png`: real `758x1024` screenshot generated
  from the public example fixture.

`AGENTS.md` is updated before these paths are created so the repository
structure contract remains authoritative.

### Updated Current-Facing Files

- `AGENTS.md`, `PLAN_web.md`, `web/README.md`, and `deploy/README.md`
- `scripts/refresh_dashboard.py` and its direct tests
- deployment verification scripts, Caddy examples, and the launchd example
- affected Trellis backend specifications

Archived Trellis tasks and Git history are evidence, not current-facing
configuration. They remain byte-for-byte unchanged.

## Public Information Boundary

Current documentation and runnable examples must not contain:

- the remembered SSH alias `myecs`;
- the live deployment IP;
- an owner home-directory path;
- historical server backup paths;
- credentials, hashes, keys, private source data, or server-generated
  artifacts.

Canonical product/runtime defaults such as `/srv/ai-desk-card/web`,
`/opt/ai-desk-card-online`, `/run/lock/ai-desk-card-refresh.lock`, widget names,
and the `758x1024` viewport are not personal data and remain where they define a
real deployment contract.

Repository history and `.trellis/tasks/archive/` are deliberately excluded
from genericization because rewriting provenance would not remove already
published objects and would damage auditability.

## Configuration Contracts

### Refresh Publisher

`scripts/refresh_dashboard.py` no longer assumes the owner SSH alias.

- `AI_DESK_CARD_SSH_HOST` supplies the default for `--host`.
- `--source-check` needs no SSH host.
- `--preview --baseline <file>` needs no SSH host.
- Any path that reads or publishes a remote baseline without an explicit host
  fails before SSH with a redacted configuration diagnostic and exit code `3`.
- Canonical remote path, backup directory, and lock path defaults stay stable.

Tests cover all four branches so removal of the implicit host cannot silently
turn into a network attempt.

### Deployment Verification

- `verify_ip_only.sh` requires either a positional URL or
  `AI_DESK_CARD_URL`.
- `verify_ip_https.sh` requires `AI_DESK_CARD_BASE_URL`,
  `AI_DESK_CARD_IP`, and the existing password input.
- Missing configuration fails before `curl`.
- Caddy IP examples use `AI_DESK_CARD_WEB_ROOT`; the IP-only example is
  explicitly a public-demo configuration and is not suitable for private
  widgets.
- The launchd file is renamed to a neutral
  `com.example.ai-desk-card-refresh.plist.example` and uses explicit path
  placeholders that the deployment guide requires operators to replace.

## README And Screenshot

The root README is concise and English-first. It covers:

1. product purpose and non-goals;
2. a real sanitized dashboard screenshot;
3. architecture and the six supported widgets;
4. a zero-build quick start using Python's static server;
5. data/configuration and privacy boundaries;
6. deterministic validation;
7. deployment, contribution, security, and license links;
8. only verified limitations.

The screenshot is generated by serving a temporary copy of `web/` in which
`widgets.example.json` is exposed as `widgets.json`. The built-in Browser uses
the canonical `758x1024` viewport. Validation records the viewport, no-scroll
result, six rendered widget types, and visual inspection before the sanitized
PNG is copied into `docs/assets/`.

The README does not claim fresh quota data, arbitrary
`refresh_seconds`-driven polling, completed waived gates, or current live
deployment health.

## Continuous Integration

CI runs on pull requests targeting `main` and pushes to `main`.

- workflow permissions are limited to `contents: read`;
- third-party actions are limited to official GitHub actions and pinned to
  full commit SHAs with release tags in comments;
- Python unit tests run through stdlib `unittest`;
- Python compile, JavaScript syntax, shell syntax, plist parsing, JSON parsing,
  plan freshness tests, and public-surface contract tests run without a package
  install;
- no secrets, live sources, SSH, deployment, browser, physical device, or
  network-dependent product tests run in CI.

The plan hook is not invoked directly from a fresh checkout because its
mtime-based worktree freshness signal is a local workflow gate. Its
deterministic logic remains covered by `scripts.test_plan_guard`.

## GitHub Repository Changes

After the implementation branch is pushed:

- create a draft PR targeting `main`, then read back its base, head, draft
  status, title, body, and checks;
- update the repository description to an accurate static-dashboard summary;
- enable private vulnerability reporting and read the setting back;
- leave branch protection, rulesets, Discussions, Pages, and all other
  repository security settings unchanged.

The default-branch community profile cannot include unmerged PR-head files, so
the task verifies the files on the PR head and records the score limitation
instead of claiming a live score increase.

## Branch Migration And Cleanup

1. Fetch `origin/main`.
2. Fast-forward local `main` to the fetched commit.
3. Create `agent/open-source-readiness` from that exact `origin/main`.
4. Carry only this untracked planning task onto the replacement branch.
5. Implement, validate, commit, push, and create the draft PR.
6. Re-fetch and prove that
   `46700de3e3ea92491981ba9c29dffe0d58a84708` is an ancestor of
   `origin/main`, that the old branch has no open PR, and that it is
   unprotected.
7. Record recovery:
   `git branch agent/phase7-planning-handoff 46700de3e3ea92491981ba9c29dffe0d58a84708`
   and the corresponding `git push origin` command.
8. Delete the approved local branch with `git branch -d`, then delete the exact
   remote branch.
9. Read back local and remote branch inventories and preserve `main` plus the
   new implementation branch.

No unresolved glob or broad branch deletion is allowed.

## Compatibility And Rollback

- Static dashboard URLs and the `widgets.json` schema are unchanged.
- Existing callers that passed `--host` continue to work.
- Existing remote workflows that relied on the implicit `myecs` alias fail
  loudly and must set `AI_DESK_CARD_SSH_HOST` or `--host`; this intentional
  compatibility break removes owner-specific behavior.
- Documentation and workflow changes can be reverted through the new branch
  commits before merge.
- GitHub private vulnerability reporting can be disabled through the same
  repository setting if rollback is required.
- The deleted old branch can be recreated from its recorded full commit ID.

## Specification Impact

The implementation updates the applicable backend specs rather than treating
the new behavior as documentation-only:

- real-data publisher configuration and failure semantics;
- backend directory ownership for the new contract test;
- quality guidance for dependency-free CI and public-surface checks;
- deployment/certificate examples where generic inputs change an executable
  contract.

Frontend runtime behavior does not change; frontend specs need no semantic
rewrite.
